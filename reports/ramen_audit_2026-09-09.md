## 已发现并修正的具体问题

| 问题 | 影响 | 当前处理与核验依据 |
|---|---|---|
| 重要性投影额外翻转 Y 方向 | 高斯可能读取图像另一侧物体的档位，影响分裂、剪枝和资源分配 | `semantic/joint.py::project_tiers_to_gaussians` 与 CUDA `ndc2Pix` 对齐，测试使用上下不同标签和图像外点 |
| 配置最高五阶 SH，CUDA 实际只算到三阶 | 四、五阶参数占用存储，不能产生所宣称的高阶颜色拟合 | 新训练最高三阶，背景/普通/重要为 `1/2/3`；核对 `semantic/presets.py`、训练入口及 CUDA 前向/反向 |
| 验证视角参与原型/PCA/编码边界拟合 | 原“验证”带有 transductive 信息，不能视为完全独立 | `--fit_exclude_list` 将验证图排除，元数据记录 `fit_image_names` 和 `heldout_image_names`；旧语义监督需重建 |
| 把早停容差同时用于选择最佳 checkpoint | 小于 0.02 dB 的真实更优权重可能没有保存 | `utils/validation_state.py` 将“更优即保存”与“显著改善才重置耐心”分开 |
| 验证语义通道/粒度随迭代变化 | 不同轮次的 L1 差异可能来自评价内容变化 | 验证固定 middle 粒度并覆盖全部通道，禁用随机对比/邻域采样 |
| top-k 强制为提示词分配区域 | 场景不存在某物体时也可能得到高重要性区域 | 仅在达到阈值的区域中选取，默认保留全部达标实例，不强制低分命中 |
| 最佳联合 checkpoint 原地恢复的优化器分组不匹配 | 已完成训练可能在最终导出/评估前中断 | 恢复时重建语义参数与优化器分组；已有回归测试 |
| 通过 mask 目录数字排序猜相机 | 相机名不匹配时可能悄悄评估错误画面 | 只接受明确名称匹配或 `--camera_map`；歧义、缺图、空 split 报错 |
| 请求等时间被当成已实现等时间 | 恢复前时长缺失仍可能宣称公平对照 | 必须有三阶段完整累计时长和完成标志，再检查显式时间容差 |

这里没有实现新的五阶 CUDA kernel，也没有将已有 v3 权重变成“修正后的模型”。
v3 联合模型已经补齐本次评估作为历史记录；验证上述训练改动需要独立 v4
数据/监督与新训练。

## 后续评估必须满足的协议

1. 使用相同的人工标注视角、相机、图像尺寸和 mask 文件。评估器现在记录这些
   项目及数据指纹；名称相同而内容或尺寸不同仍不算同口径。
2. 保持语义阈值 `0.25`、middle 粒度 `1`、`boundary_ratio=0.008`，记录评估代码
   版本。阈值调优应在验证方案内完成，不使用最终测试标注调参。
3. `test_psnr` / `test_ssim` 仅表示 annotated 视角；可选 `all_test_rgb` 独立保存
   全部测试相机结果，禁止用一个字段替补另一个字段。
4. 记录 `weight_selection`、`validation_summary.json`、实际训练轮次及最佳来源。
   验证预处理必须排除验证图；旧文件不满足条件时不能直接复用为 v4 监督。
5. 等时间需要联合、顺序 RGB、顺序语义三段真实累计时长。历史不完整则标记
   “不能认证等时间”，不推算丢失时间；预处理、评估与备份成本另外列出。
6. 报告至少包含 PSNR、SSIM、mIoU、Boundary-IoU、逐类别结果、高斯数量及三级
   重要性结果。背景没有独立完整人工标注时标为未测，不用 `1−前景 IoU` 推算。

新评估器同时保存 GT/RGB 渲染并排图与人工/预测 mask 在同一 GT 上的叠加图。
它们可用于检查细长物体断裂、边界外溢和错误相机映射；可视化应与指标属于
同一 checkpoint，清理版场景的结果必须另存，不覆盖原始模型对照。

语义特征、相机/配置、数据划分、预处理元数据、计时日志和评估。最优与最新

副本、未被当前任务使用的临时文件，以及由本恢复流程自身备份清单管理的旧
滚动 checkpoint。先确认精确路径、引用关系和替代副本；当前模型唯一权重、
唯一源数据、唯一语义预处理或用户其他云盘文件不属于自动清理候选。

新的滚动备份应先完成复制并验证文件尺寸/稳定性，再替换清单、轮换自身记录
中的旧副本。运行时 `/content` 数据不是持久备份；Drive 挂载显示的可用空间
也不应直接等同于 Google 账号剩余配额。磁盘或账号配额不足时保留已有结果与
本地日志，记录备份失败，不能把未落盘的文件记为已安全保存。
